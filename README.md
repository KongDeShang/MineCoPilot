# 矿山智工 · 设备健康智能体

面向矿山工程机械运维的**全离线**设备全生命周期工作台。

一台笔记本、不联网、不调用任何云端大模型 API，完成从台账导入 → 健康评分 → 告警 → 工单 → 复诊闭环 → 备件扣减 → 经验沉淀的全流程，且**每一个数字都能追溯到它的来源**。

> 参赛：第十五届中国创新创业大赛 · AI+工程机械专业赛
> 详细材料见 [`docs/参赛材料.md`](docs/参赛材料.md)，演示流程见 [`docs/演示脚本.md`](docs/演示脚本.md)，验收结论见 [`docs/测试报告.md`](docs/测试报告.md)，视觉规范见 [`docs/视觉规范.md`](docs/视觉规范.md)，资料落地见 [`docs/资料落地.md`](docs/资料落地.md)

```bash
npm install
```

首次启动自动播种一套**确定性**演示数据（固定随机种子 `20260912`）：60 台设备、70 张工单、164 条维修记录。每次重置得到的数据完全一致 —— 演示不会"这次和上次不一样"。

## 为什么值得看

### 1. 数字不编造：规则引擎算，大模型只说人话

这是本项目的核心设计取舍。

现场数据不能出本机，所以**没有任何云端 AI**。但小参数模型（本地内置 Qwen2.5-0.5B-Instruct，Q4_K_M 量化，468 MB）直接做数值推理并不可靠 —— 它会自信地编出一个看起来很像的停机损失。

所以系统把职责切开：

```
规则引擎（确定性计算，出所有数字）
        ↓  只把已核实的结论交出去
    本地模型（只做叙述润色，不参与任何计算）
        ↓  出口处校验数字不变量
   生成文本里的每个数字必须 ⊆ 规则引擎给出的数字集合
```

- 出口校验：`verifyNumbersSubset()`（`src/renderer/src/utils/llmClient.js`）
- 提示词硬约束写在引擎层，不在界面层：`SYSTEM_PROMPT`（`src/main/llmEngine.js`）
- 任何一环失败（模型未加载 / 生成失败 / **数字对不上**）→ 静默回退到规则引擎的原始结论，绝不把可疑输出放给用户
- 装机自检 `runSelfVerify()`：加载 + 生成 + 校验数字不变量，结果落盘 `userData/llm-verify.json`

也就是说：**大模型的失败模式是"少说"，不是"说错"**。

### 2. 每个结论都可审计：健康分拆到因子级

健康分不是一颗黑盒分数，而是四个可解释因子相加（`src/renderer/src/utils/health.js`）：

| 因子 | 规则 | 上限 |
|------|------|------|
| 维保及时性 | 每超期 1 天扣 2 分；无维保记录扣 30 分 | 扣分 ≤ 45 |
| 设备机龄 | 超过 5 年后每多 1 年扣 5 分 | — |
| 故障状态 | 当前处于故障状态扣 30 分 | — |
| 数据完整度 | 购置日期/上次维保/设备型号每缺一项扣 5 分 | — |

分档 A(≥85) / B(70–84) / C(55–69) / D(<55)，并有**强制升级**：超期 > 30 天至少 C 级、> 45 天至少 D 级、故障状态直接 D 级 —— 不允许"分数好看"盖过现场事实。

每个因子都会同时输出 `{ 扣分, 计算式, 数据来源 }`，界面上、导出的体检报告里都能看到完整算式，例如：

> 距上次维保 140 天 − 周期 90 天 = 超期 50 天，每超期 1 天扣 2 分 → 扣 100 分，单因子上限 45 分，实际扣 45 分

停机损失同样是公开公式：

```
预计损失 = 风险系数 × 日产出假设 × 预估停时
预估停时 = min(20, max(3, 超期天数 × 0.3) + (故障 ? 5 : 0))   天
```

日产出按机型取值（矿卡 12 万/日、破碎机 9 万/日、挖掘机 8 万/日……），风险系数按等级取值并夹在 [0.1, 0.9]。全部常量与算式在界面上可查、可按矿种切换预设场景（露天铁矿 1.6 / 砂石骨料 1.0 / 基建施工 0.55）。

### 3. 闭环是真的闭上的

```
Excel 台账导入 ──→ 健康评分 ──→ 告警扫描 ──→ 工单 ──→ 完成并归档
                      ↑                                    │
                      └────── 7 天后复诊 ←──────────────────┘
                                   │
                              复诊仍异常 → 再开工单
```

- **工单完成**会自动写入设备病历、生成 7 天后的复诊任务
- **维保记录里填了配件**会真的扣减备件库存，并在备件流水里留痕
- **同设备同系统故障 ≥ 3 次**会自动提炼成知识库草稿（`ai_draft`），积累成"经验传承"
- 现场录一条规程 → AI 助手**立刻**能检索到并作答

### 4. 离线不是口号，是可以验证的

- `src/` 内**除开发模式下加载本地 Vite 服务外，没有任何对外网络请求**，没有任何 API key
- Electron：`contextIsolation: true` / `nodeIntegration: false`，preload 只通过 `contextBridge` 暴露白名单方法，不透传 `ipcRenderer`
- 外部链接一律交给系统浏览器打开（`setWindowOpenHandler` 返回 deny）
- 数据库是纯 JS 的 SQLite（sql.js），Electron 下落盘为 `userData/kuangshan-zhigong.db`，浏览器下走 IndexedDB，再降级到 localStorage
- 随包的 3 份示例手册是仓库内的本地文件（`src/renderer/public/manuals/`），不联网取；装完后由主进程复制进 `userData/documents/`，该目录之外的文件一律拒绝打开与删除
- 一键导出/导入 `.mbak` 备份（整库字节 + 对话历史）

## 功能一览

侧边栏 5 个分组、15 个入口：

| 分组 | 页面 |
|------|------|
| 设备健康 | 数据看板、设备台账、设备病历 |
| 运维执行 | 告警中心、维保日历、工单管理、复诊管理 |
| AI 智能 | AI 助手、本地模型、维修规程库、手册资料库 |
| 数据资产 | 故障案例库、备件库存、操作日志 |
| 系统 | 系统设置 |

几个值得一提的：

- **AI 助手**：统一输入框，自动分流到 *查询*（查台账/知识库）或 *写入*（口述建单）。写入类必须先在"理解卡"里确认才落库。
- **口述录入**：支持 7 类意图（建维修工单 / 完成工单 / 记录维保 / 改设备状态 / 完成复诊 / 写知识库 / 查询）。设备指代有 6 级匹配（全名 → 别名 → 型号+序号 → 类别+序号 → 纯型号 → 模糊打分），**任何一层出现多个候选就停下来问，绝不猜**。执行前有预检（如"没有未完成工单"会直接拦下），执行后可一键撤销。
- **维修规程库**：内置 30 条规程（16 条徐工机型专属），12 个系统分类，33 组同义词。检索按"标题命中 +12 / 分类 +4 / 关键词命中 +3 / 同义词扩展 +2"打分排序 —— 问"挖机水温高"也能命中《发动机过热 / 水温偏高》。
- **备件库存**：与维保记录用的是同一份件名目录，所以"记录里写了换件"和"库存里扣了件"不会各说各话。
- **手册资料库**：装完就有 3 份真手册（SQ10SK3Q 随车吊 36 页 / XCA60E 全地面吊 32 页 / QY25K5D 汽车吊 18 页，共 4.8 MB）。手册不是摆设——有文字层的那几份可直接向 AI 提问，回答注明《手册名》第 N 页；扫描件如实降级为"仅查看"，不硬撑。文字层在构建期抽好随包发（首次启动现抽要十几秒），文件与检索全程在本机。
- **操作日志**：所有写入留痕并落库，刷新不丢 —— 这是"可审计 AI"的证据链，演示时可当场点开给评委看。

## 验收

四套脚本，**全部可一条命令跑通**（不需要事先手工开终端起服务器）：

```bash
npm run lint        # 静态检查（只拦真错，不管风格）
npm run self-check  # 275 条核心逻辑断言
npm run coverage    # 口述指代消解的功能覆盖矩阵
npm run e2e         # 86 条无头浏览器端到端（真实点击真实路由）
npm run e2e:nl      # 28 条口述录入端到端（含撤销、歧义、不误写）

npm run verify      # 以上全部 + 生产构建
```

当前状态：**lint 0 错 0 警 / self-check 275 通过 / e2e 86 通过 / e2e:nl 28 通过 / 运行时异常 0**。

静态检查刻意只启用 `vue/essential` 而不用 `recommended` —— 后者一半是排版规则，接入当天会刷出上千条格式告警，真正的 bug 会被淹没。其中显式启用了 `vue/no-undef-properties`：模板里调用一个没导入的函数会导致整页白屏，而这类错误自检和端到端都可能漏掉，必须靠静态检查兜住。

> **`verify` 全绿不等于界面没问题。** 两套端到端断言的是"数据和交互对不对"，而对比度、布局遮挡这类**视觉缺陷它结构上抓不到** —— 一个文字读不出来的标签、一个被固定列盖住的关键列，在 DOM 层都是"存在、可见、文案正确"的。本次打磨中抓出的两个高严重度缺陷（见 [`docs/测试报告.md`](docs/测试报告.md) #20 #21）正是这样漏过去的，靠无头浏览器批量截图逐张看图才发现。视觉这一层目前**靠人工过截图**，尚未自动化。

## 已知边界（不粉饰）

以下是**当前版本确实没做**的，写在这里以免误解：

- **语音识别未实现**，拍照 OCR 为演示用的模拟结果（真实版本可替换为 Tesseract.js 本地识别）
- **撤销栈只在内存里**，刷新后失效（最多 20 步）
- **本地模型的显存/内存需求没有给出实测数值**，只有"纯 CPU 推理、无需 GPU"的定性结论
- Electron 的 `sandbox` 未开启（`contextIsolation` 与 `nodeIntegration: false` 已开启）
- 演示数据是程序生成的，非真实矿山数据；矿区名称使用"云南××矿区"这类脱敏写法
- **随包手册只有 3 份**（起重/随车吊）。主力机型挖掘机的完整手册（XE210C 英文、XE215C 俄文、XE230_XE250C 英文）不是中文，没随包 —— 它们的内容已提炼进维保项目库与故障现象库，条目上注有手册页码。要换成别的机型手册，改 `src/renderer/src/utils/bundledDocs.js` 并重跑 `node scripts/build-manual-assets.mjs`（需本机有《资料/》目录）
- **扫描件手册只能"仅查看"**：没提取到文字层就如实降级，不硬撑成"可问答"，也不假装引用过它

界面层（设计令牌见 [`docs/视觉规范.md`](docs/视觉规范.md)）：

- **视觉无自动化回归**：改了样式只能靠人过截图，没有基线比对（见上"验收"一节的说明）
- **首次启动没有骨架屏**：首启要播种 60 台设备 + 导入 3 本手册，这段时间界面是空白的。补骨架屏需要 store 的 loading 状态，会动到状态层，暂缓
- **窄于 1200px 时表格回退到横向滚动**：未做响应式隐藏列（工单表已把「复诊」列前移，保证被挤出视野的是时间/来源而非闭环状态）
- **数据看板状态条仍用 emoji 图标**（💰⚠️🔒），未换成 `el-icon`
- 深色底目前只有落地页与侧栏两处；若后续加深色主题，`--on-dark-*` 语义色需要补齐
