# 矿山智工 · 5 分钟演示脚本

> 面向评委现场演示。总时长 **5 分钟**，每段标注了秒数与**卡点风险**。
> 演示前请先执行「§零 开场准备」，并读过「§六 故障预案」。

---

## 零、开场准备（演示前 5 分钟做完）

```bash
npm run dev        # 浏览器演示（推荐，稳定、启动快）
# 或
npm run electron:dev   # 需要展示本地大模型时用这个
```

1. **重置到干净状态**：左下角 `重置演示数据` → 弹窗点 `确认重置`
   - 预期结果：数据看板显示 **60 台设备**、闭环率 **63%**
   - 这一步很重要：所有数字都会回到确定值，演示可复现
2. **打开两个窗口/标签**：一个停在数据看板，一个备用
3. **断网**（如果场地允许）：拔网线或关 Wi-Fi。系统照常工作 —— 这本身就是最强的演示点
4. **浏览器缩放调到 100%**，关闭其它占用麦克风/摄像头的程序
5. **试按一次右上角 `引导演示`**，确认 12 步能走完

### 兜底：右上角 `引导演示`（30 秒～2 分钟）

页面右上角有一颗 `引导演示` 按钮，点下去会自动按顺序走完上面的主线：
看板 → 设备台账 → 设备病历 → 工单 → AI 助手 → 维修规程库 → 复诊 → 本地模型，
共 **12 步**，带遮罩高亮和进度（`3 / 12`），可用 `上一步` / `下一步` 自行控制，`×` 随时退出。

什么情况下用它：

- **讲超时了**：§二～§四 是弹性最大的三段，时间不够就直接跳过，改用引导演示把主线补全
- **评委要求"再走一遍"**：不用重新组织语言，按一下就是同一条叙事、同一个节奏
- **现场只有一台设备、评委自己上手看**：让他自己按，比在旁边解说更可信

注意：引导演示是**兜底**，不能替代 §一 的断网演示和 §五 的"它敢说不知道"——
那两处是全场最有说服力的点，必须亲口讲。

## 一、开场：断网（30 秒）

**做**：把笔记本转过来，指着 WiFi 图标显示已断开。

**说**：

> 矿山的数据 —— 设备参数、产量、故障记录 —— 是商业机密，也是安全数据，不能上传公有云。
> 所以这个系统**从设计上就不联网**。现在我把网断掉，接下来的每一个操作，都在这台笔记本上完成。

**为什么要这样开场**：一句话把"离线"从口号变成评委亲眼所见的事实，也自然引出后面"那 AI 从哪来"的疑问。

---

## 二、数据整合：多份格式不同的 Excel（1 分钟）

**做**：
1. 进 `AI 助手` 页 → 找到 Excel 导入面板
2. 点 `下载示例模板`（会生成 5 份格式各不相同的示例：设备清单 / 维保记录 / 巡检记录 / 配件库存 / 资产表）
3. 一次性把几份拖进去 → 自动识别表头并合并

**说**：

> 现场的真实情况是：生产部、采购部、维修部各发一份表，表头写法都不一样 —— 有的写"设备名称"，有的写"名称"。
> 系统做两轮表头识别，先精确匹配、再模糊匹配，然后按标准字段对齐合并。
> 注意这里：**多份表是自动合并的，不需要人工对齐列**。

**卡点风险**：拖拽在部分远程桌面/投屏环境下会失效。
**预案**：改用面板里的文件选择按钮，或直接用已导入好的台账（示例数据已含 60 台）。

---

## 三、健康分与可审计性（1 分钟）

**做**：
1. 进 `数据看板`，指出顶部四个数字与"高频故障 TOP"
2. 进 `设备台账` → 找一台 **D 级**设备 → 点 `体检`
3. 报告弹出后，**逐条念出四因子的算式**

**说**：

> 健康分不是一颗黑盒分数。它由四个因子相加，每个因子都给出**扣了多少分、按什么公式扣的、数据来自哪条记录**。
>
> （指着具体一行念）"距上次维保 140 天，减去周期 90 天，等于超期 50 天；每超期 1 天扣 2 分，该扣 100 分，但单因子上限 45 分，所以实际扣 45 分。"
>
> 停机损失也是公开公式：风险系数 × 日产出 × 预估停时。日产出按机型取值 —— 矿卡 12 万一天，破碎机 9 万，挖掘机 8 万。
>
> **评委老师可以现场随便挑一台设备、挑一个数字，我们都能倒推出它是怎么来的。**

**为什么这段最重要**：评委见过太多"AI 给个分"的产品。可审计性是本作品与它们的根本区别。

**卡点风险**：翻找 D 级设备耗时。
**预案**：提前记下一台 D 级设备的名称（重置后位置固定，可先演练一次记下来）。

---

## 四、口述录入：一句话变成工单（1 分钟）

**做**：
1. 进 `AI 助手`
2. 输入：`3 号挖掘机液压油压力偏低`
3. 出现**理解卡**（此时还没写库）→ 指给评委看
4. 点 `确认` → 工单落库
5. 再演示一次**歧义**：输入 `装载机轮胎漏气了`（不带序号）
   - 会出现候选列表，**确认按钮是禁用的**
6. 最后演示**撤销**：左侧边栏最下方点 `撤销上次写入`

**说**：

> 现场工程师不可能坐下来填表格。所以他直接说一句人话。
>
> 注意第二点：我说"装载机"但不带序号 —— 系统**不知道我指哪一台**。
> 它没有猜，而是把候选全列出来让我选，而且**确认按钮是灰的** —— 在有歧义的情况下，它拒绝写入。这是安全边界，不是功能缺失。
>
> 写进去之后如果发现说错了，一键撤销，数据回到写入前。

**卡点风险**：示例数据里装载机数量较多，候选列表可能较长。
**预案**：先说第一句（明确指代）保证主流程顺，歧义演示作为加分项，时间不够可跳过。

---

## 五、AI 可信：它敢说"我不知道"（1 分钟）

**做**：
1. 在 `AI 助手` 提问：`3 号挖掘机水温高怎么处理？`
2. 展开 `智工分析过程`，指出：查台账 → 算四因子 → 检索规程库 → 生成结论
3. 指出回答下方的**引用规程**（带书名号与出处）
4. **关键一击**：故意问一个知识库没有的问题，例如 `帮我写一首关于春天的诗`
5. 它会明确回答"本地知识库中没有检索到……"，并列出覆盖范围

**说**：

> 每个回答都能展开"分析过程"，告诉你它查了哪张表、检索到几条规程、依据是什么。
>
> 现在我问一个它答不上来的问题。
>
> （等结果）"本地知识库中没有检索到……" —— **它说不知道，而不是编一个答案给我**。
>
> 这是我们在架构上做的取舍：数字由规则引擎算，本地小模型只负责把结论说成人话；
> 而且模型输出的每个数字都要回头校验，必须原结论里有才能通过，否则**整段丢弃**、直接回退到规则引擎的原文。
> 换句话说，**这个大模型的失败方式是"少说"，不是"说错"**。

**卡点风险**：模型加载需要时间（Electron 模式下首次加载约几秒）。
**预案**：本段主流程走的是规则引擎 + 规程库检索，**不依赖模型加载**，即使模型没就绪也照样能演示；模型可用时结论会更口语化。

---

## 六、闭环：工单完成之后（30 秒）

**做**：
1. 进 `工单管理` → 找一张进行中的工单 → 标记完成
2. 显示"已归档至某某设备病历，7 天后复诊"
3. 进 `复诊管理` → 指出刚生成的那条复诊任务
4. 进 `操作日志` → 指出刚才所有操作的留痕
5. 进 `备件库存` → 指出维保记录里填的配件**真的扣了库存**，且流水可查

**说**：

> 很多系统的"闭环"停在把工单标成完成。我们的闭环是真的往下走：
> 完成 → 自动归档设备病历 → 自动生成 7 天后复诊任务 → 复诊仍异常就再开工单。
> 维保记录里填了配件，备件库存会真的扣减并留下流水。
> 所有写入都在操作日志里留痕 —— 这一页就是我们说的"可审计 AI"的证据链。

**收尾一句**：

> 整套系统一台笔记本、不联网、不需要 GPU，装机即用。

## 七、故障预案

| 可能出问题 | 现象 | 处理 |
|---|---|---|
| 端口被占 | `npm run dev` 起不来 | 换端口 `npm run dev -- --port 5180` |
| 数据被改乱 | 数字与预期不符 | 点 `重置演示数据`（3 秒恢复固定值） |
| 模型加载失败 | 本地模型页显示未就绪 | **不影响主流程演示**（见 §五 预案），跳过模型对比环节即可 |
| 拖拽失效 | Excel 拖不进去 | 改用文件选择按钮，或跳过导入、直接看已导入的台账 |
| 断网后页面刷新失败 | 白屏 | 开发模式下页面本身来自本地服务，断网不影响；若已刷新失败，说明 dev server 未启动，改用 Electron 模式 |
| 现场只能在评委电脑上跑 | 无法 npm 安装 | 准备 `electron:build` 产出的安装包（NSIS），双击安装即用 |

### 打包便携版（现场兜底用）

```bash
npm run electron:build
# 产物：release/矿山智工-1.0.0-setup.exe
```

> 注意：模型文件 468 MB 会一并打进安装包，实测最终包体 **627 MiB**（本机构建，插件与模型都随包）。拷贝到 U 盘前先确认目标机器有足够空间。
> 包体的大头是模型与原生推理后端，不是代码：`app.asar` 本身已压到 15.1 MiB，再优化前端也带不动总量。

## 八、常见提问与准备答案

**Q：为什么用 0.5B 这么小的模型？**
> 因为它不需要 GPU、不需要大显存，一线工程师现有的办公笔记本就能跑。而它算不准数字 —— 所以我们的架构里**它根本不参与计算**，只负责把规则引擎已经核实过的结论说成人话。选型是被"必须离线 + 必须可信"这两个约束倒推出来的。

**Q：那 AI 含量是不是不够？**
> 我们的 AI 用在三处：设备指代的语义解析（6 级匹配 + 歧义消解）、规程库的相关度检索与同义词扩展、以及叙述层的大模型润色。**算数字用规则引擎不是妥协，是审计要求** —— 矿山设备停机损失直接影响决策，一个不可复算的数字是不可接受的。

**Q：数据从哪来？是真的吗？**
> 演示数据是程序按固定种子确定性生成的，机型取自公开可查的真实型号目录，矿区名做了脱敏。系统支持导入现场真实的 Excel 台账。

**Q：能接实时测点数据吗？**
> 当前版本还没有实现 IoT 测点接入，数据来自导入和手工/口述录入。这是我们 V1.0 的规划内容，接口层已经预留。

**Q：现场没网怎么安装？**
> 提供离线安装包，内置模型文件，双击安装即用，无需联网激活。
