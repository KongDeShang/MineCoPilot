## 一、资料来源与性质

25 份 PDF，全部来自**公开渠道**（徐工各国官网、公开手册库、经销商公开资料），
**不含**徐工内部受控技术文件（深度维修手册、液压/电气原理图全集等无法公开获取）。

下载时间：2026-09-13。

**来源站点**：

- **徐工官网**（xcmg.com）：XC978 产品手册等（PDF 直链可下载，页面有限流）

## 二、25 份资料的三种去向

资料不是摆着看的。按"用得上 / 随包发 / 有意不用"分三类：

| 类 | 份数 | 去向 |
|---|---|---|
| **A. 提炼进代码** | 8 | 维保项目库、故障现象库、机型白名单、车队构成 |
| **B. 随包发出** | 3 | `src/renderer/public/manuals/`，装完就能在手册库看到 |
| **C. 有意不用** | 14 | 港口 / 大吨位吊装 / 塔机 / 滑移等，**不属于矿用车队构成** |

### A 类：提炼进代码（8 份）

| 资料 | 落到项目哪里 | 落地形态 |
|---|---|---|
| `LW188_轮式装载机_维护手册.pdf` | `utils/equipmentCatalog.js` → `MAINTENANCE_LIBRARY` | 6 级保养周期（50/100/250/500/1000/2000 h + 季节性）逐条照搬；机油/液压油/润滑脂牌号、胎压与制动参数取手册原值 |
| `XE210C_挖掘机操作维护手册.pdf` | `utils/equipmentCatalog.js` → `FAULT_LIBRARY` | 22 条故障现象的真实疑似原因，**条目上方注明手册页码**（P127/P130/P131/P135/P136 等） |
| `XE215C_挖掘机_操作维护手册_俄文.pdf` | 同上（交叉印证） | 机型与故障现象覆盖度核对 |
| `XE230_XE250C_挖掘机_操作手册.pdf` | 同上（交叉印证） | 同上 |
| `徐工叉车系列_技术规格书.pdf` | `utils/equipmentCatalog.js` → `MODEL_WHITELIST` | 叉车线 3 个型号（XCB-P20 / P35 / PW50，按 VDI2198 标注载重）。该规格书**没有保养/故障章节**，故未提炼 |

| 其余产品样本 / 技术规格书 | `MODEL_WHITELIST` + `FLEET_MIX` | 机型谱系与吨位分布（15t 小挖 → 25t 主力 → 49t → 80t 矿用），保证演示台账里的型号**公开可查** |

> **可从代码回溯**：出处写在 `equipmentCatalog.js` 里每段数据上方的注释中，不是靠这份表口口相传。

### B 类：随包的哪三份，为什么是它们

`src/renderer/src/utils/bundledDocs.js` 里登记清单，`src/renderer/public/manuals/` 下是产物。

| 手册 | 页 | 文字层 | 大小 | 随包后用户能做什么 |
|---|---|---|---|---|
| SQ10SK3Q_随车起重机_操作维护手册 | 36 | 36 页 | — | 手册库直接看到，可打开原文，也能向 AI 提问并得到「第 N 页」出处 |
| XCA60E_全地面起重机_规格书 | 32 | 32 页 | — | 同上（机型参数问答） |
| QY25K5D_汽车起重机_技术规格书 | 18 | 18 页 | 共 4.8 MB | 同上 |

**三条挑选口径，缺一不可**：

1. **中文可读** —— 演示与问答都是中文语境
2. **有文字层** —— 扫描件只能"仅查看"，做不了带页码出处的问答
3. **是车队在管机型** —— 手册能挂到设备档案上

主力机型挖掘机的完整手册（XE210C 英文 / XE215C 俄文 / XE230_XE250C 英文）**都不是中文，因此没有随包** —— 它们的内容已按机型提炼进维保项目库与故障现象库（即 A 类）。

这三条口径由 `npm run self-check` 守着（I2 组）：机型必须在白名单内、必须出现在车队构成里。**口径由机器验证，不靠人记。**

### C 类：有意不用的 14 份

港口正面吊（XCS4545K）、港口牵引车（XPT75E）、重卡牵引车（XGA4181D5NA）、大吨位履带吊（XGC12000 / XGC15000A / XLC17000）、塔机（XGT7528A-18S1 / XGTL120）、越野轮胎吊（XCR30 / XCT35 / QY25K5-II / QY25K5 boomlift）、伸缩臂叉装机（XC6-3507K）、滑移装载机（XC7-SR07）。

**理由**：这套系统演示的是**矿山车队**的运维闭环。把港口机械和 1250t 履带吊塞进演示台账，机型谱系就假了 —— 评委一眼能看出这不是一个真实矿山的车队构成。**宁可少，不可假。**

## 三、这批资料守住了什么

| 卖点 | 资料如何支撑 |
|------|-------------|
| "每个数字都能追溯到来源" | 故障现象条目上注手册页码；维保周期取手册原值 |
| "演示数据不是编的" | 机型全部公开可查；吨位分布有据 |
| "离线可用" | 3 份真手册是仓库内本地文件，装完后由主进程复制进 `userData/documents/`，不联网取 |
| "AI 回答注明出处" | 随包手册有文字层 → 回答能给出《手册名》第 N 页 |

## 四、资料更新后怎么重新生成

产物是从 `资料/` 目录抽取的，**不在该目录**，所以改完资料要重跑一次：

```bash
node scripts/build-manual-assets.mjs   # 需要本机有《资料/》目录
```

它按 `bundledDocs.js` 的清单，把每份 PDF 抽成 `public/manuals/<slug>.pdf`（原件）+ `<slug>.json`（逐页文字层，带页码）。

**为什么在构建期抽而不是首次启动时抽**：启动时解析 30~200 页 PDF 要十几秒，用户看到的是"手册库卡住了"。

要换成别的机型手册：改 `src/renderer/src/utils/bundledDocs.js` 并重跑上面的脚本。
