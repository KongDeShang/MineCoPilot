# 矿山智工 · 视觉规范

> 这份文档回答一个问题：**改界面时，颜色/字号/圆角/阴影该从哪里取，以及有哪些坑。**
> 令牌定义在 `src/renderer/src/styles/tokens.css`，由 `main.js` 先于业务样式引入。

---

## 一、为什么要有令牌层

`tokens.css` 不是一开始就有的。项目初期的做法是**每个页面各写各的色值**，后果是同一个语义在不同页面长得不一样：

| 问题 | 具体表现 |
|------|---------|
| 配色分裂 | 全站存在 **四套** 蓝：Element Plus 默认 `#409eff`、品牌深空蓝 `#0b3a82`、落地页自己一套石板蓝 `#0c1426→#1a2744→#0d1b2e`、侧栏又一套渐变 |
| 对比度失守 | `#909399`（3.08:1）、`#c0c4cc`（1.75:1）被当作次要文字用，低于 WCAG AA 的 4.5:1 |
| 状态色混用 | 把标签**底色**的色值直接拿来写**文字**（如 `#e0a020` 当字色 → 2.28:1） |
| 改一处漏五处 | 同一个 `pending` 的文案、颜色、圆角在 4 个地方各写一份 |

令牌层解决的是"**同一个语义只有一处定义**"。落地后 `var(--token)` 引用数从 **2 处 → 671 处**。

> **注（2026-09-24）：落地页已删除。** 本文有多处拿落地页当深底基准，现已改为以**侧栏**为准 ——
> 该页删除后，全站深底只剩侧栏这一处。原落地页源码在 git 历史里（删除它的那个提交）。

## 二、令牌分组与选用规则

### 2.1 文字：用 `--text-*` 这一组，不要用调色板

```
--text-1     主正文 / 标题      白底 18.5:1
--text-2     次要文字           白底  8.8:1
--text-3     弱化文字 / 标签    白底  6.0:1
--text-mute  占位符 / 装饰      白底  4.34:1
```

`--ink / --ink-2 / --ink-3 / --ink-4` 是**调色板**，不是正文用色。`--text-mute` 只允许出现在 placeholder、分隔符、图表网格、禁用态这类"非必须读"的位置 —— 不得当正文。

### 2.2 状态色分"面"和"字"两套

这是本项目踩过的坑：标签底色可以浅，但**文字必须够深**。

| 用途 | 令牌 | 对比度 |
|------|------|--------|
| 面（背景/边框） | `--emerald` / `--amber` / `--danger` / `--signal` 及 `-soft` `-line` | — |
| 字（彩色文字） | `--success-ink` `--warn-ink` `--danger-ink` `--signal-ink` | 全部 ≥ 4.5:1 |

**规则**：`el-tag` 的底色交给 Element Plus 的主题变量（`--el-color-success-light-9` 等），文字颜色用 `--*-ink`。直接 `color: var(--amber)` 会得到 2.28:1。

### 2.3 深色底必须换一组（`--on-dark-*`）

浅色那组令牌换到深底上会**直接失效**：`--text-1 #0a1326` 压在 `#0c1426` 上只有 **1.02:1** —— 看着有颜色，其实读不出来。`--danger #e0413e` 在深底也只有 4.37:1。

所以深底（侧栏）单独一层：

```
--on-dark-1       主文字          12.0:1
--on-dark-2       次要文字         6.8:1
--on-dark-3       弱化文字 / 说明   4.8:1
--danger-on-dark                  4.6:1
--emerald-on-dark                 5.6:1
--amber-on-dark                   7.5:1
--signal-bright   品牌标记        12.7:1
```

选值标准：在深底**最亮的那一段**上也 ≥ 4.5:1。原先按落地页三段里最亮的 `#0b2a5c` 标定；
该页删除后深底只剩侧栏，其渐变顶端 `--accent`（`#0b3a82`）**比 `#0b2a5c` 更亮**，余量因此比当初标定时更小 ——
侧栏到底达没达标，以 `npm run audit:contrast` 的实测为准（它按实际计算值判，不依赖这句标定）。

> 重新着色深底元素时，别忘了 hover 态 —— 改色后原本的 hover 变暗可能不再明显。本项目对深底链接的做法是保留原 token + `filter: brightness(1.15)`。

### 2.4 其他

| 组 | 令牌 | 备注 |
|----|------|------|
| 圆角 | `--r-lg` 18 / `--r` 13 / `--r-sm` 10 / `--r-xs` 7 / `--r-pill` | `--el-border-radius-base` 已同步为 10px |
| 阴影 | `--sh-xs` / `--sh-sm` / `--sh-md` / `--sh-kpi` / `--sh-focus` | 数据密集界面用 `--sh-xs` 为主，`--sh-md` 留给浮层 |

### 2.5 Element Plus 主题覆盖

`tokens.css` 里一次性替换了全站组件库默认蓝 —— primary / success / warning / danger / info 五组各 7 档色阶，外加文字、边框、填充、背景、圆角、字体。**组件库的样式不要在页面里再覆盖一遍**，改颜色请改这里的 `--el-*`。

## 三、三个必须知道的坑

### 坑 1：SVG 表现属性不解析 `var()`

```html
<!-- ✗ 不生效，元素拿到字面量 "var(--danger)"，浏览器丢弃 -->
<path :stroke="risk.color" />

<!-- ✓ 二选一 -->
<path :style="{ stroke: risk.color }" />   <!-- inline style 允许 var() -->
```

CSS 规则里的 `stroke:` / `fill:` 声明**可以**用 `var()`：

```css
.risk-arrow { stroke: var(--danger); }   /* ✓ */
```

因此 `utils/health.js` 里 `RISK_LEVELS` 的颜色保持**字面量 hex**（它们经 `:stroke` 绑定），而 `TREND_KINDS` 用的是 `var(--token)`（它们经 `:style="{ color }"` 绑定）。

### 坑 2：`el-icon` 的 `color` prop 走 CSS 变量，所以 `var()` 生效

`el-icon` 把 `color` prop 落成 `--color` 自定义属性，因此：

```html
<el-icon color="var(--signal-bright)">…</el-icon>   <!-- ✓ -->
```

### 坑 3：表格列宽 —— `width` 不收缩，`min-width` 才会

Element Plus 表格里，**固定 `width` 的列不会收缩**；`min-width` 的列会吸收多余空间、窄窗口下收缩到自己的最小值。当 Σ(列宽) > 可用宽度时，出现水平滚动，**固定列会盖住被挤出去的列**。

工单表的实际教训：原配置固定宽度合计 1210px > 1440 窗口下的可用约 1149px，导致「复诊」列被右侧 `fixed="right"` 的「操作」列遮住 —— 闭环状态是这套系统的卖点，却被 UI 藏了。

现在的配平（1440 下可用 ≈ 1149px，1280 下 ≈ 990px）：

- 固定宽度列合计 **796**，`min-width` 列最小值合计 **314**，总最小 **1110**
- 标题、关联设备用 `min-width` + `show-overflow-tooltip`，多余空间由它们吸收，窄窗口优先压缩
- **把「复诊」移到「来源 / 创建时间」之前** —— 窄窗口时牺牲的是时间与来源，而不是闭环状态

## 四、全局一致性层

`tokens.css` 末尾有一层"每个页面都该有、但没人愿意在 15 个页面里各写一遍"的规则。**全部是纯样式，不涉及任何组件结构、props、事件或状态**：

| # | 规则 | 解决的问题 |
|---|------|-----------|
| 1 | `:where(...):focus-visible` 焦点环 | 此前全站 `:focus-visible` 为 **0 处**，键盘操作完全不知道焦点在哪。用 `:where()` 把特异度压到 0，保证 Element Plus 自己的聚焦样式仍能覆盖。深底上换成信号青 |
| 2 | `prefers-reduced-motion` 收敛动效 | 站内有路由过渡、常驻呼吸点、图表入场动画，对前庭功能敏感的用户是真难受 |
| 3 | `tabular-nums` | 工单号、健康分、金额用比例字形时，位数一变整列左右抖动 |
| 4 | 表格行内边距 `8px 0` | 默认值下 1440×900 工单表首屏只看得到 11 行 |
| 5 | `.cell:empty::after` → `—` | 工单表里有不少没填标题的行，空着看起来像数据丢了。只命中真为空的单元格（有选择框/展开箭头的不是 `:empty`） |
| 6 | 过渡时长统一 | 见 2.4 |
| 7 | `body { font-size: var(--fs-body); line-height: 1.5 }` | 此前 `body` 没有任何字号规则，实际吃浏览器默认 16px —— 令牌里的 `--fs-body` **从没生效过**（实测 computed 16px） |

## 五、改界面的自检清单

改完视觉后逐条过一遍：

- [ ] 新增/修改的色值来自令牌，没有新的字面 hex（`tokens.css` 自身除外）
- [ ] 深底元素用的是 `--on-dark-*`，不是 `--text-*`
- [ ] 彩色文字用的是 `--*-ink`，不是状态底色
- [ ] 绑到 `:stroke` / `:fill` 的颜色是字面 hex，不是 `var()`
- [ ] 改过颜色的元素，hover / active / disabled 态仍然看得出来
- [ ] 窄窗口（1280）下关键列没被固定列遮住
- [ ] 键盘 Tab 一遍，焦点始终可见
- [ ] `npm run verify` 全绿（**不是**只跑 lint）
