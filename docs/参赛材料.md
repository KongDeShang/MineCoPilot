# 矿山智工 — 中国创新创业大赛参赛材料

## 一、作品信息

- **作品名称**：矿山智工
- **英文名**：MineSmart AI
- **赛道**：AI+运维应用
- **一句话定位**：面向工程机械运维工程师的本地离线 AI 工作台，告别混乱表格、人脑记忆、纸笔记录

## 二、项目背景与痛点

### 行业现状

矿山现场工程师和工程机械售后运维工程师面临四大数字化痛点：

| 痛点 | 具体场景 | 影响 |
|------|---------|------|
| **多部门 Excel 混乱** | 生产部、采购部、维修部各发一份 Excel，格式不统一、字段冲突 | 数据整合耗时，易出错 |
| **维保靠人脑记忆** | 200 台设备的保养周期、历史故障、配件更换全凭经验 | 遗漏即停机，单次损失数十万 |
| **工业数据不能上云** | 设备参数、产量数据、故障记录属于商业机密/矿山安全数据 | 无法使用公有云 AI 服务 |
| **现场纸笔 → 二次录入** | 巡检只能手写记录，回办公室再录系统 | 效率低、易出错、信息滞后 |

### 真实场景

> 老王是某矿山的设备运维工程师，管理 50 台挖掘机和装载机。
> 每天面对 5 个部门发来的 Excel 表格，格式各不相同。
> 去年漏了一台挖掘机的液压油更换，停机 3 天损失 40 万。
> 现场巡检只能纸笔记录，回办公室再花 2 小时录入系统。
> 而这些数据涉及矿山产量和设备参数，**绝对不能上传到公有云大模型**。

## 三、解决方案

### 产品架构

```

│              用户终端（笔记本/平板）                 │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ Excel导入 │ │ 语音录入  │ │ 拍照OCR  │          │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘          │
│       └────────────┼────────────┘                 │
│                    ▼                              │
│  ┌─────────────────────────────────────┐          │
│  │       矿山智工 AI 工作台             │          │
│  │  ┌────────┐ ┌────────┐ ┌────────┐   │          │
│  │  │数据清洗 │ │维保提醒 │ │智能问答 │   │          │
│  │  │ Agent  │ │ Agent  │ │ Agent  │   │          │
│  │  └────────┘ └────────┘ └────────┘   │          │
│  │       本地推理引擎（离线运行）        │          │
│  └─────────────────────────────────────┘          │
│                    ▼                              │
│  ┌─────────────────────────────────────┐          │
│  │        SQLite 本地数据库             │          │
│  │  设备台账 | 维保记录 | 工单 | 知识库   │          │
│  └─────────────────────────────────────┘          │
└──────────────────────────────────────────────────┘
```

### 四大核心 Agent

| Agent | 功能 | 技术方案 |
|-------|------|---------|
| **数据清洗 Agent** | 拖入混乱 Excel → 自动识别表头 → 结构化入库 | SheetJS + 字段映射规则引擎 |
| **维保提醒 Agent** | 设备台账 + 维保规则 → 到期主动提醒 | SQLite + 定时计算 |
| **语音/OCR Agent** | 语音转工单 + 拍照识别巡检单 | Web Speech API + Tesseract.js |
| **智能问答 Agent** | "3号挖掘机上次换液压油是什么时候？" | 本地大模型 + 设备知识库 |

### 离线 AI 推理

- 本地部署轻量大模型（Qwen2.5-7B）
- 8GB 显存笔记本即可运行
- 所有推理在本地完成，数据不出设备

## 四、技术方案

| 组件 | 选型 | 理由 |
|------|------|------|
| 前端框架 | Vue 3 + Element Plus | 组件丰富，开发效率高 |
| 桌面框架 | Electron | 跨平台，Web 技术栈 |
| 构建工具 | Vite | 快速热更新 |
| 数据库 | sql.js | 纯 JS，零部署，单文件 |
| Excel 解析 | SheetJS | 前端直接解析，无需后端 |
| 语音识别 | Web Speech API / Whisper.cpp | 浏览器原生 / 离线 |
| OCR | Tesseract.js / PaddleOCR | 浏览器端 / 离线 |
| 大模型 | llama.cpp + Qwen2.5-7B | 本地推理，中文效果好 |

## 五、竞品分析

| 维度 | 传统设备管理系统 | SaaS 运维平台 | **矿山智工** |
|------|----------------|--------------|------------|
| 数据安全 | 本地部署但笨重 | 数据上云 ✗ | **本地优先 ✓** |
| AI 能力 | 无 | 有但依赖云端 | **本地离线 AI ✓** |
| 离线使用 | 部分支持 | 不支持 | **完全离线 ✓** |
| 现场录入 | 纸笔 → 二次录入 | 需联网 | **语音/拍照一步到位 ✓** |
| 部署成本 | 高（需服务器） | 按年付费 | **装机即用，零运维 ✓** |

## 十、演示脚本（5 分钟）

### 场景设定
老王是某矿山的设备运维工程师，管理 50 台挖掘机和装载机。

### 演示流程

1. **开场（30s）** — 展示痛点：桌上一堆 Excel，手机里拍的模糊照片，手写的巡检本
2. **Excel 导入（1min）** — 拖入 3 个不同部门的 Excel → 自动识别合并 → 展示结构化设备台账
3. **语音建工单（1min）** — "3 号挖掘机液压油压力偏低，需要安排更换" → 自动识别设备、故障类型、生成工单
4. **拍照记录（1min）** — 拍摄一张手写巡检表 → OCR 识别 → 自动填充到系统
5. **智能问答（1min）** — "17 号装载机保养周期是什么？上次什么时候保养的？" → 本地 AI 回答
6. **维保提醒（30s）** — 展示设备到期提醒列表，点击查看详情
