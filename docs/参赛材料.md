# 矿山智工 — 中国创新创业大赛参赛材料

> 本文档描述的功能**以代码实现为准**。凡是当前版本没做的，都写在「§十一 已实现 / 未实现清单」里，不做模糊表述。

## 一、作品信息

- **作品名称**：矿山智工 · 设备健康智能体
- **赛道**：AI+工程机械专业赛（AI+运维方向）
- **一句话定位**：不联网、不调云端大模型，在一台笔记本上完成矿山设备全生命周期运维的本地 AI 工作台
- **核心主张**：**规则引擎出数字，本地大模型只说人话；每个数字都能追溯到来源**

## 二、项目背景与痛点

### 行业现状

| 痛点 | 具体场景 | 影响 |
|------|---------|------|
| **多部门 Excel 混乱** | 生产部、采购部、维修部各发一份 Excel，表头不统一、字段冲突 | 人工整合耗时，易出错 |
| **维保靠人脑记忆** | 上百台设备的保养周期、历史故障、配件更换全凭经验 | 遗漏即停机，停机损失按日产出计价 |
| **工业数据不能上云** | 设备参数、产量、故障记录属商业机密与矿山安全数据 | 公有云 AI 服务用不了 |
| **现场纸笔 → 二次录入** | 巡检手写记录，回办公室再录系统 | 效率低、易出错、信息滞后 |

### 真实场景

> 老王是某矿山的设备运维工程师，管着 50 多台挖掘机和装载机。
> 每天面对好几个部门发来的 Excel，格式各不相同。
> 去年漏了一台挖掘机的液压油更换，停机 3 天。
> 现场巡检只能纸笔记录，回办公室再花 2 小时录入。
> 而这些数据涉及矿山产量和设备参数，**绝对不能上传到公有云大模型**。

## 三、解决方案

### 产品架构

│  │      工单流转 / 复诊闭环 / 备件扣减             │      │

### 与传统"AI 运维助手"的关键区别

一般做法是把数据丢给大模型让它算。本项目**反过来**：

| | 常规做法 | 矿山智工 |
|---|---|---|
| 谁算数字 | 大模型 | **规则引擎**（确定性、可复算） |
| 大模型干什么 | 计算 + 回答 | **只把已核实的结论改写成人话** |
| 大模型算错怎么办 | 用户无从察觉 | **出口校验数字不变量，不通过就丢弃它的输出** |
| 大模型不可用 | 功能降级/不可用 | 回退到规则引擎原文，**功能不降级** |
| 可审计性 | 黑盒 | 每个因子给出 `{扣分, 计算式, 数据来源}` |

**大模型的失败模式是"少说"，不是"说错"。** 这是本项目在"必须离线 + 必须可信"双重约束下的核心工程取舍。

### 四大能力模块（对应代码实现）

| 模块 | 实现 | 位置 |
|------|------|------|
| **数据整合** | 拖入多份格式不一的 Excel → 两轮表头识别（先精确后模糊）→ 按标准字段对齐合并 → 结构化入库 | `utils/excelParser.js` |
| **健康评估** | 四因子可解释评分 + 分档 + 强制升级 + 停机损失公开公式 | `utils/health.js` |
| **口述录入** | 自然语言 → 7 类意图 → 设备指代 6 级匹配 → 歧义必问 → 预检 → 确认落库 → 可撤销 | `utils/nlCommand.js`、`stores/nlActions.js` |
| **智能问答** | 先查真实台账，再查规程库（相关度打分），未命中明确说"查不到"而不编造 | `utils/knowledgeBase.js` |

## 四、技术方案

| 组件 | 选型 | 理由 |
|------|------|------|
| 前端框架 | Vue 3 + Element Plus + Pinia | 组件完整，开发效率高 |
| 桌面框架 | Electron | 跨平台；`contextIsolation` + preload 白名单 |
| 构建 | Vite | 快速热更新 |
| 数据库 | sql.js（纯 JS SQLite） | 零部署、单文件；Electron 落盘 `userData/*.db`，浏览器走 IndexedDB |
| Excel 解析 | SheetJS | 前端直接解析，无需后端 |
| 本地推理 | node-llama-cpp + Qwen2.5-0.5B-Instruct Q4_K_M | **纯 CPU**，模型 468 MB，装机即用 |
| PDF | pdfjs-dist | 手册资料库本地解析 |

### 本地模型的真实规格

| 项 | 值 |
|---|---|
| 模型 | Qwen2.5-0.5B-Instruct |
| 量化 | Q4_K_M |
| 体积 | 468.6 MB（491,400,032 字节） |
| 推理后端 | node-llama-cpp，纯 CPU，**无需 GPU** |
| 上下文 | 1024 |
| 生成参数 | maxTokens 128 / temperature 0.2 / topP 0.9 |
| 角色 | **仅叙述层润色，不参与任何数值计算** |
| 装机自检 | 加载 + 生成 + 校验数字不变量，结果写 `userData/llm-verify.json` |

> 选 0.5B 而不是 7B，正是因为它**不需要 GPU、不需要大显存**，可以在一线工程师现有的办公笔记本上直接跑起来。它算不准数字，所以我们就干脆不让它算 —— 这是本项目最重要的设计决定。

### 离线与安全

- `src/` 内**无任何对外网络请求、无任何云端 API key**（唯一例外是开发模式加载本地 Vite 服务）
- `contextIsolation: true`、`nodeIntegration: false`；preload 只经 `contextBridge` 暴露白名单方法，不透传 `ipcRenderer`
- 外部链接一律交由系统浏览器打开
- 数据可一键导出为 `.mbak` 备份（整库字节 + 对话历史），随时可搬走

## 五、竞品分析

| 维度 | 传统设备管理系统 | SaaS 运维平台 | **矿山智工** |
|------|----------------|--------------|------------|
| 数据安全 | 本地部署但笨重 | 数据上云 ✗ | **本地优先 ✓** |
| AI 能力 | 无 | 依赖云端 | **本地离线 AI ✓** |
| 断网可用 | 部分支持 | 不支持 | **完全离线 ✓** |
| AI 可信度 | — | 黑盒输出 | **数字可溯源 + 出口校验 ✓** |
| 部署成本 | 高（需服务器） | 按年付费 | **装机即用，零运维 ✓** |

## 十、演示脚本（5 分钟）

完整分镜见 [`演示脚本.md`](演示脚本.md)。概要：

1. **开场（30s）** — 断网演示：拔掉网线，系统照常工作
2. **数据整合（1min）** — 拖入 3 份格式不同的 Excel → 自动识别合并 → 60 台设备台账
3. **健康与可审计（1min）** — 打开一台 D 级设备体检报告，逐条念出四因子算式与来源
4. **口述录入（1min）** — "3 号挖掘机液压油压力偏低" → 理解卡 → 确认 → 工单落库 → 一键撤销
5. **AI 可信（1min）** — 提问 → 看分析过程与引用规程 → 故意问一个知识库没有的问题，看它明确说"查不到"
6. **闭环（30s）** — 完成工单 → 自动生成 7 天后复诊 → 病历归档 → 操作日志留痕

## 十一、已实现 / 未实现清单

### 已实现（有代码、有验收脚本覆盖）

- Excel 多文件导入合并（14 个标准字段、两轮表头识别、5 份示例模板）
- 四因子健康评分 + 分档 + 强制升级 + 可配置场景预设（3 种矿种）
- 停机损失测算（公开公式、按机型日产出、风险系数夹取）
- 告警扫描与处置（处置状态随库持久化，刷新不丢）
- 工单全流程 + 完成后自动归档病历 + 生成 7 天复诊任务
- 备件库存与维保记录联动扣减（同一份件名目录，扣减留流水）
- 口述录入 7 类意图、歧义必问、预检拦截、一键撤销
- 知识库 30 条规程 / 12 分类 / 34 组同义词，按相关度打分检索
- 同设备同系统故障 ≥3 次自动提炼知识草稿
- 本地大模型叙述层 + 数字不变量出口校验 + 失败静默回退
- 全局搜索（顶栏，跨设备/工单/维保记录，支持直达定位）
- 操作日志留痕并落库（滑动窗口保留最近 500 条）；`.mbak` 一键备份导入导出
- 手册资料库（PDF 本地解析，随包 3 份真手册开箱可看、可问答）；故障案例库；本地模型管理页
- 引导演示（右上角一键播放的 12 步主线，默认手动点一步走一步、可切自动；首启自动弹一次，供评委自行走查）
- Electron 渲染进程三重隔离：`contextIsolation: true` + `nodeIntegration: false` + `sandbox: true`，
  原生能力只经 preload 白名单暴露
- 九条验收命令（一条 `npm run verify` 按序跑完全部）：lint / self-check / main-check / store-check / coverage / build / e2e / e2e:nl / 对比度审计；**断言条数以脚本末行"合计 N 项"为准**，本文不写死数字
  - 各网专责：`self-check` 本地核心逻辑（日期、sql.js 落盘往返、Excel 解析、知识库检索）；`main-check` 主进程契约（IPC 注册与来源校验、切档失败不得改变当前档位、拉不到远端清单时回退内置）；`store-check` 状态层（首启播种闸门、字段白名单回读、落盘失败必须仍是脏状态、重置演示数据后撤销栈清空）；`coverage` 口述指代消解的**能力覆盖矩阵**（明确不是代码覆盖率）；`e2e` 无头浏览器走真实交互；`e2e:nl` 口述录入链路（理解卡 → 歧义必问 → 确认 → 落库 → 刷新仍在 → 撤销 → 纯查询不误写）；`audit:contrast` 双主题文字对比度是否达 WCAG AA

### 未实现（当前版本确实没有）

- **语音识别**：未实现
- **OCR**：拍照识别为演示用的模拟结果，未接入真实识别引擎
- **撤销覆盖范围**：只有口述录入 / AI 助手的写入可撤销；工单完成按钮、复诊、备件出入库、设备增改、Excel 导入、备份导入都没有撤销。撤销栈本身**已作跨刷新持久化**（最多 20 步，落本机 localStorage，超预算从最早的淘汰并记日志），且带 CAS —— 写入后又被改过的记录**拒绝**自动回退，不做静默覆盖
- **部分失败不回滚到底**：撤销逐条执行，失败的项会明确报出原因，但已回退的部分不会自动复原（该条撤销记录随即作废，剩下的需手工处理）
- **本地模型资源占用实测值**：未测，仅有"纯 CPU、无需 GPU"的定性结论
- **多终端同步 / 企业版私有化部署**：规划内容
- **测点实时数据接入（IoT）**：未实现，当前数据来自导入与手工录入

### 演示数据说明

演示台账由程序确定性生成（固定种子 `20260912`）：60 台设备、69 张工单、352 条维保记录、290 条健康快照、18 张故障案例卡、3 份随包示例手册。机型取自公开可查的真实型号目录（32 个型号 / 10 个类别，含徐工与他牌混编），矿区名使用"云南××矿区"这类脱敏写法，**不含任何真实客户数据**。

其中维保项目库与故障现象库的内容来自公开手册（LW188 装载机维护手册的 6 级保养周期、XE210C 挖掘机操作维护手册的故障排查表，条目上注有手册页码），故障案例卡则由"已完成的维修工单"派生——症状是工单原文，原因/处理取自知识库命中的条目，**可逐张追溯到来源工单**。
