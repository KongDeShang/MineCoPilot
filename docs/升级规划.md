## 二、批次 0 · 域化架构（架构地基）

**目标**：从「appStore 1090 行 + 66KB 工具文件混装」→「域 = 数据表 + 页面 + 动作 + 命令 + 能力声明」。

**域的标准结构**：

```
domains/<name>/
  domain.js       状态、动作、持久化映射（对应现在 stores/ 里的一块）
  routes.js       页面路由注册
  commands.js     命令面板命令注册
  capabilities.js 声明依赖的 AI 能力（narrate/diagnose/summarize/asr/ocr/parse）
  views/          本域页面
```

**关键原则**：
- **渐进迁移，不一次性推翻**：新域直接按新架构写；旧域（设备/工单/备件/知识库）一个一个搬，每搬完一个跑 `npm run verify` 兜底。
- **跨域联动走接口**：工单归档→备件扣减等跨域动作定义「事件/服务钩子」，不直接互相改状态。
- **注册中心**：启动时扫描 `domains/` 生成侧边栏菜单、路由表、命令表、能力依赖图。

**落点**：新增 `domains/` 目录 + `registry.js`；appStore 瘦身为「全局壳 + 跨域协调」。
**工作量**：5-7 人天（分散在各批次，非一次性大重构）。
**风险**：重构回归——288 self-check + 88 e2e 是迁移安全网。

## 三、批次 1 · 能力地基

### 3.1 模型可插拔升档

**目标**：`llmEngine.js` 从「写死一个 0.5B」→「模型注册表 + 会话管理」，模型成为可切换服务。

**档位设计**（Q4_K_M 量化）：

| 档位 | 模型 | 体积 | 建议配置 | 能力边界 |
|------|------|------|---------|---------|
| 轻量（默认） | Qwen2.5-0.5B（现用） | 468MB | 任何笔记本 | 叙述润色、关键词检索（现状） |
| 标准 | Qwen2.5-1.7B / Qwen3-1.7B | ~1.1GB | ≥8GB 内存 | + 多轮诊断对话、纪要提炼、意图理解 |
| 增强 | Qwen3-4B | ~2.5GB | ≥16GB 内存 | + 复杂排障推演、长文本总结 |

**关键设计**：
- **能力分级声明**：每档声明能力（narrate/diagnose/summarize），功能按档位灰度，档位不够入口自动隐藏。
- **自动选档**：启动探测内存 + 实测推理速度，自动选默认档；「本地模型」页可手动覆盖。
- **懒加载与释放**：首次用到才加载；切档先释放旧 session 再加载新档，不占双份内存。
- **数字不变量铁律不下放**：任何档位输出必须过 `verifyNumbersSubset()`，不通过回退规则引擎原文。

**落点**：`llmEngine.js` 拆为 `ModelRegistry.js` + `ModelSession.js`；`ModelHub.vue` 升级为「模型中心」；preload 增加 `llm.listModels / llm.switchModel`。
**里程碑**：M1 注册表+自动选档（不动生成逻辑）→ M2 切换与释放 → M3 能力分级（1.7B 启用诊断对话）。
**工作量**：2-3 人天（核心）。**风险**：安装包膨胀（由 3.2 分发方案消化）。

### 3.2 模型云端分发（双轨 · 一次联网永久离线）

**目标**：模型从安装包拿出放云端，首次安装一键选择下载嵌入，此后完全离线。

**双轨**：

| 轨道 | 内容 | 体积 | 场景 |
|------|------|------|------|
| A. 在线安装包（主推） | 不含模型，首次启动弹「模型选择向导」 | ~150MB | 有网用户、评委装演示机 |
| B. 完整离线包（兜底） | 内置 0.5B | ~627MB（现状） | 矿场/无网环境、评审现场兜底 |

**轨道 A 体验流程（3 次点击以内）**：
安装启动 → 检测无模型弹向导 → 按内存自动推荐档位、点「下载」→ 后台下载（进度 + 断点续传 + 可跳过）→ SHA-256 校验 → 落 `userData/models` → 自动跑装机自检（复用 runSelfVerify）→ 「模型已就绪，可断网使用」。

**关键设计**：
- 云端清单 `models.json`：id/名称/档位/体积/所需内存/能力边界/SHA-256/版本/URL/许可声明（Qwen 为 Apache-2.0，可再分发）。
- 下载管理器 `modelManager.js`（主进程）：HTTP Range 断点续传、进度事件推送、SHA-256 校验失败即弃重试、失败不阻塞主流程（AI 降级规则引擎）。
- 本地模型目录**双源合并扫描**：`resources/models`（随包）+ `userData/models`（用户下载，可写可删）；manifest.json 本地登记；多档共存、切档懒加载。
- 下载源**多镜像**：`models.json` 配多个 URL，主源挂自动换备用源。
- 模型版本管理：清单带版本，检测旧版提示「一键换新」（删+重下），防止 userData 堆积旧模型。
- 下载源推荐：对象存储（阿里 OSS / 腾讯 COS / Cloudflare R2），国内带宽稳、支持 Range；GitHub Releases 作备用。

**答辩话术**：> 「安装包轻量化到 1/4；模型是一次性可选下载的离线资产，下载后断网可用；运行期零联网、数据不出本机。」

**落点**：新增 `src/main/modelManager.js`；改 `llmEngine.js` modelDir() 合并扫描；改 `preload/index.js` 暴露 `models.list/download/delete/verify`；新增 `components/ModelWizard.vue` + 升级 `ModelHub.vue`；改 electron-builder 配置（A 不打包 models，B 保留 extraResources）。
**工作量**：4-6 人天。**风险**：断点续传与大文件下载需实测；下载源网络质量决定首次体验。

### 3.3 统一文档解析

**目标**：PDF / Excel / Word 解析收敛为统一 `docService`，任何域「丢进一个文件 → 拿到结构化文本」。

**接口**：`parse(file) → { format, name, pages, text, tables[], images?, raw }`

| 格式 | 方案 | 说明 |
|------|------|------|
| PDF | pdfjs-dist（已有） | 按需加载，扫描件如实降级「仅查看」 |
| Excel | SheetJS（已有） | 多 Sheet 合并为 Markdown 表格文本 |
| Word .docx | **新增 mammoth.js** | 纯 JS、零 .node，符合离线铁律 |
| txt/md | 直接读 | — |
| 老 .doc | 明确不支持 | 界面提示转存，诚实边界 |

**关键设计**：
- **文本层缓存**：解析结果按「文件哈希+大小」缓存到本地，二次打开秒出（一并解决手册库首启抽文字层十几秒的问题）。
- **与 RAG 打通**：解析文本按页/章节切片进统一切片池，AI 助手立即可问。
- **统一错误语义**：结构化返回「扫描件无文字层/格式不支持/文件损坏」，各域不各自写 try/catch。

**落点**：新建 `utils/docService/`（index.js + adapters/pdf.js + excel.js + word.js）；`ExcelImportPanel`、`Documents.vue`、`bundledDocs.js` 改走统一入口；vite manualChunks 给 mammoth 独立 chunk。
**工作量**：3-4 人天。**风险**：低；注意 mammoth 的 docx 版本兼容。

## 四、批次 2 · 展示层（见效最快，多数可并行）

### 4.1 深色主题

- `tokens.css` 扩展 `html[data-theme="dark"]` 全套令牌：背景阶梯、边框、文本、`--on-dark-*` 语义色、A/B/C/D 等级色暗底适配。
- Element Plus 官方暗色方案（`html.dark` + CSS 变量覆盖）与自有令牌对齐。
- 设置页三选：浅色/深色/跟随系统（`prefers-color-scheme`），偏好存 meta 表。
- **对比度门禁扩展**：`scripts/contrast-audit.mjs` 加深色参数，16 条路由深色下再跑 WCAG AA。
- 落点：tokens.css、App.vue、Settings.vue、contrast-audit.mjs。工作量 3-4 人天。

### 4.2 数据大屏模式

- 新路由 `/big-screen`（独立页面）：全屏暗底、大字号、核心指标（设备总数/运行率/健康分布/停机损失），30 秒自动刷新，Esc 退出。
- 复用 `AnimatedNumber` + 现有 SVG 饼图 + ECharts 趋势。
- 入口：Dashboard 右上角「进入大屏」；引导演示增加「大屏线」。
- 落点：`views/BigScreen.vue` + 路由。工作量 2-3 人天。

### 4.3 多视图切换

- `ViewSwitcher.vue` 通用组件：列表（现有表格）/ 卡片（网格）/ 图表（ECharts 概览）/ 时间线（el-timeline）四视图。
- 首批接入：设备台账、工单管理、备件库存；视图偏好持久化 localStorage。
- 落点：`components/ViewSwitcher.vue` + 3 个视图渲染组件。工作量 3-4 人天。

### 4.4 Ctrl+K 命令面板

- `Ctrl+K` 唤起，模糊搜索（含拼音首字母）。
- 四类命令：导航（15 页）/ 动作（建单、记维保、导出报告）/ 查询（融合 GlobalSearch）/ AI（自然语言转 AI 助手）。
- **命令注册表**：各域 `registerCommands()`，新域加命令不改面板本体（呼应域化架构）。
- 落点：`components/CommandPalette.vue` + GlobalSearch 改造。工作量 2-3 人天。

### 4.5 报告导出增强

- 报告类型：设备群月报 / 运维周报 / 体检报告（已有，补趋势对比段）。
- 输出：HTML（打印友好版式，浏览器打印成 PDF）/ CSV（明细导出）。
- **数据来源标注**：每个统计数字旁标注「规则引擎实时计算 / 工单表归档」，延续可审计卖点。
- 签名区：尾页留负责人/日期签字位。
- 落点：`reportGenerator.js` 扩展 + `components/ReportPreview.vue`。工作量 3-4 人天。风险：PDF 中文走浏览器打印，不引重量级 PDF 库。

### 4.6 引导演示增强

- 多路线：主线（现有 12 步）+ AI 能力线 + 大屏线；路线即 JSON 配置。
- 路线编辑器（开发/演示前用）：页面、高亮元素、气泡文案、下一步，配置存本地。
- 自动演示模式：自动点击/切换 + 进度条 + 暂停/继续。
- 演示工具条：悬浮「上一步/下一步/计时/重置」。
- 落点：`demoTour.js` 重构为「路线解析器 + 播放器」+ 配置目录。工作量 3-4 人天。注意自动演示的异步等待。

## 五、批次 3 · 新功能域：语音纪要域

**目标**：录音 → 转写 → 纪要 → 待办转工单，本地完成。第一个按域化架构落地的样板域。

**流程设计**：
1. **录音**：MediaRecorder（Electron/浏览器均可用），时长/波形可视化，存 `userData/recordings/`（与 documents 同级边界）。
2. **转写**：依赖真实 ASR（sherpa-onnx 中文，本地几十 MB）。⚠️ ASR 不做真则本域仍是演示样例——第一版可降级为「粘贴/导入文本」入口，把「演示样例」留给后续。
3. **纪要提炼**：本地 LLM 输出结构化 JSON `{ 结论[], 待办[{事项,负责人?,期限?}], 涉及设备?, 时间点[] }`——**需要 1.7B 档**（联动 3.1）；输出过数字/结构校验，失败回退原文摘要。
4. **落库**：新表 `meeting_notes(id, title, duration, transcript, summary_json, todos_json, created_at)`；待办可「一键转工单」（调工单域接口）。
5. **界面**：新页面「语音纪要」——左侧录音列表（卡片）+ 右侧详情（转写全文 + 纪要卡片 + 待办清单 + 转工单按钮）。

**落点**：新域 `domains/meeting/`（domain.js + MeetingNotes.vue + 表结构迁移）；主进程录音/ASR IPC。
**工作量**：5-7 人天（含 ASR 接入）。**风险**：ASR 准确率（矿区噪音/术语）——演示用安静环境，sherpa-onnx 支持热词表可配。

## 八、风险与边界

| 风险 | 等级 | 缓解 |
|------|------|------|
| 模型体积膨胀（1.7B/4B） | 中 | 3.2 双轨分发，0.5B 随包兜底 |
| 低配机器跑 1.7B 慢 | 中 | 自动选档 + 能力分级，档位不够入口隐藏 |

| 深色主题视觉回归 | 中 | 对比度门禁扩展 + 截图基线（建议本轮顺带引入） |
| 域化重构回归 | 中 | 每迁移一个域跑 verify；新代码先按新架构写 |
| 下载源网络质量 | 中 | 多镜像 + 断点续传 + 失败不阻塞 |

**明确不做（本阶段）**：模型微调（K）、传感器接入（S）、局域网多端协同（G）、移动端/扫码（H）、数字孪生/3D（I）、预测性维护（C）——成本高或偏离「单机离线工作台」叙事，赛后规划。
