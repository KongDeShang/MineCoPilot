# 任务 15：语音纪要域（录音 → 转写 → 纪要 → 待办转工单）

## 背景

- 现状：AI 助手页（`views/AIAssistant.vue`）的语音/OCR 入口是**演示样例**（预置文本，界面已诚实标注"演示样例"标签）；项目无任何真实语音能力。
- 目标：落地第一个按域化架构（任务 05）生长的**新功能域**——录音 → 转写 → 纪要 → 待办转工单的完整本地闭环。
- 依赖：任务 05（域结构 + 注册中心）、任务 06（模型可插拔——**纪要提炼需要 1.7B 档**，0.5B 干不了结构化提炼；若机器只有 0.5B，纪要功能按能力分级隐藏/降级为原文摘要）。
- 诚实边界：**转写需要真实 ASR**（sherpa-onnx 中文，纯本地 WASM/N-API，几十 MB）。本任务包含 ASR 接入；若集成受阻，第一版降级为"粘贴/导入文本"入口（界面如实标注），转写通道留接口。
- 铁律：录音文件存 `userData/recordings/`（与 documents/ 同级的目录边界，主进程校验路径，参照 `docs:addFile` 的 `resolveInDocs` 模式）；全程本机处理。

## 目标

1. 新域 `domains/meeting/`：表结构（`meeting_notes`）+ 页面（录音列表 + 详情）+ 动作（录音/转写/纪要/转工单）+ 命令（注册到 Ctrl+K）；
2. 录音：MediaRecorder，时长/波形可视化，存本地；
3. 转写：sherpa-onnx 中文 ASR（或降级"粘贴文本"入口）；
4. 纪要：本地 LLM（1.7B 档）从转写文本输出结构化 JSON `{ 结论[], 待办[{事项,负责人?,期限?}], 涉及设备?, 时间点[] }`，过结构校验，失败回退原文摘要；
5. 待办一键转工单（调工单域接口，工单类型 repair）。

## 实现要点

- **录音**：优先渲染层 MediaRecorder（`audio/webm`），停止后把 Blob 经 IPC 存 `userData/recordings/<时间戳>.webm` 并登记；Electron 主进程侧可加 `getUserMedia` 权限处理（`session.setPermissionRequestHandler` 允许麦克风）。录制中波形用 `AnalyserNode` + canvas 轻量绘制。
- **ASR**：sherpa-onnx 有 WASM 与 Node 两种接入；优先 Node 版（主进程）保持与 LLM 同侧；模型文件（如 `sherpa-onnx-zh` 流式模型，几十 MB）按任务 07 的分发模式放 `userData/models/` 或独立 `resources/asr/`。若 WASM 版在渲染层跑，注意包体与线程。**若 2-3 天内接不通，按降级方案交付并如实说明**。
- **纪要提炼 prompt**（铁律：模型只提炼，不创造）：给转写全文 + 固定 JSON 模板，要求只抽取原文出现的事项；输出先过 JSON 解析 + 字段校验，任何一项失败 → 回退"原文摘要"（截取转写前 N 字）并标记 `summary_mode:'fallback'`。
- **转工单**：待办项点击"转为工单"→ 调工单域 `addWorkOrder({ title, equipment_name?, type:'repair', source:'语音纪要', description: 原文片段 })`；设备名若在纪要中解析到则自动填入，否则留空由用户选。
- **表结构**：`meeting_notes(id TEXT PK, title, duration_sec, audio_path, transcript, summary_json, todos_json, created_at)`；迁移版本号递增（database.js 有 `runMigrations` 机制，参照 knowledge_base 加列的方式）。
- **域注册**：侧边栏新分组「AI 智能」或独立分组"语音纪要"（按任务 05 注册中心规则）；Ctrl+K 命令可用（任务 12 已支持注册命令）。

## 验收标准

1. 录音可开始/停止/回放，文件落 `userData/recordings/`，列表按时间展示；
2. 转写（或降级粘贴文本）→ 纪要 → 待办展示完整；转写为降级模式时界面如实标注；
3. 纪要 JSON 结构正确；待办可一键转工单且工单在「工单管理」可见、状态机正常；
4. 只有 0.5B 档时：纪要功能隐藏或明确显示"需要标准档模型"，不硬撑；
5. 路径安全：录音文件删除/打开复用 documents/ 的 `resolveInDocs` 式边界（在 recordings/ 内）；
6. `npm run verify` 全绿（新增 e2e：建纪要→转待办→转工单→断言工单存在）。

## 注意

- 本任务**最大风险是 ASR 集成**；先花半天验证 sherpa-onnx 在你的目标平台（Windows x64 Electron）能否跑通，再决定完整/降级交付，不要拖到最后。
- 录音与纪要涉及用户隐私，仅本机存储、不联网上传；界面可加"数据本地保存"说明。
- 数据库改动仅限新增 `meeting_notes` 表（database.js 允许的最小改动），不动既有表结构与迁移逻辑。
