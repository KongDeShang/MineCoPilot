# 任务 09：深色主题（--on-dark-* 令牌 + 切换）

## 背景

- 现状：`src/renderer/src/styles/tokens.css`（18KB）已有完整浅色设计令牌层（CSS 自定义属性），`README.md`「已知边界」明确点名："深色底目前只有落地页与侧栏两处；若后续加深色主题，`--on-dark-*` 语义色需要补齐"。
- 目标：浅/深主题切换 + 补齐 `--on-dark-*` 语义色；深色主题同时服务任务 10（大屏模式）与演示场景。
- 风险：README 已承认"视觉无自动化回归，改样式靠人过截图"——本任务必须把 `scripts/contrast-audit.mjs`（现有 16 路由文字配色对比度 WCAG AA 门禁）扩展出深色模式，这是唯一的自动化保障。

## 目标

1. `tokens.css` 扩展 `html[data-theme="dark"]` 全套令牌（背景阶梯/边框/文本/语义色/等级色暗底适配）；
2. 设置页三选：浅色 / 深色 / 跟随系统，偏好存 meta 表，启动即应用（不闪白）；
3. Element Plus 暗色方案（`html.dark` + CSS 变量覆盖）与自有令牌对齐；
4. `contrast-audit.mjs` 支持深色模式参数，16 条路由深色下跑 WCAG AA。

## 改动清单

| 文件 | 动作 | 说明 |
|------|------|------|
| `src/renderer/src/styles/tokens.css` | 扩展深色令牌 | `html[data-theme="dark"] { ... }` + `--on-dark-*` 全套 |
| `src/renderer/src/App.vue` | 主题初始化/切换 | 读 meta → 应用 `data-theme` + EP `html.dark`；`matchMedia('(prefers-color-scheme: dark)')` 监听 |
| `src/renderer/src/views/Settings.vue` | 主题设置项 | 三选 radio + 说明；写入 meta |
| `src/renderer/src/styles/driverTheme.css` | 深色适配 | 引导遮罩在深色下可读 |
| `scripts/contrast-audit.mjs` | 深色参数 | 如 `--theme dark`：注入 `data-theme=dark` 后跑现有 16 路由断言 |
| `src/renderer/src/views/*`（15 页） | 逐页核对 | 硬编码色值（`#fff` 背景、`#333` 文字等）改走令牌；这是最耗时部分 |

## 实现要点

- **令牌层级**：浅色在 `:root`，深色在 `html[data-theme="dark"]` 覆盖同名令牌；新令牌命名沿用现有风格（`--bg-*`、`--text-*`、`--border-*`、`--on-dark-*`）。
- **等级色**：`health.js` 里 `RISK_LEVELS` 的 `color`/`ink` 是给 SVG 用的字面 hex（SVG 表现属性不解析 var()，这是项目已踩过的坑），深色下等级色**仍用同一套 ink/color**（它们已满足白底/白字对比度），不要为深色改它们；等级色在深色卡片上的使用靠卡片背景令牌配合。
- **不闪白**：主题在 `bootstrap()` 早期应用（读 meta 在挂载前）；或用 `index.html` 内联最小脚本先设 `data-theme`（注意 CSP 下内联脚本需放行或改由主进程注入）。
- **逐页核对方法**：全局搜 `#fff`、`#333`、`#666`、`background: white`、`color: #` 等硬编码，替换为对应令牌；列表/表格/卡片在深色下逐一过截图。
- **对比度脚本**：深色模式下拉起 dev server（现有 contrast-audit 已有浏览器驱动基础），注入主题后复用现有断言函数。

## 验收标准

1. 三选切换即时生效；重启后偏好保持；跟随系统随系统切换；
2. 深色下 15 个页面可读：无白底残留、无黑字黑底、表格/弹窗/图表图例清晰；
3. `npm run contrast` 与深色变体均通过（浅色 16 路由 + 深色 16 路由）；
4. 引导演示（driver.js 遮罩）在深色下可读；
5. `npm run verify` 全绿（对比度脚本更新后自检相应更新）。

## 注意

- 只做主题层，不改任何业务逻辑；不改 health.js 的等级色。
- 深色是全局改动，**逐页截图核对是硬验收**（README 已警告视觉缺陷靠 DOM 断言抓不到），不要只跑自动化就宣布完成。
- 若某页深色下实在难处理（如图表配色），如实报告并记录遗留，不悄悄绕过。
