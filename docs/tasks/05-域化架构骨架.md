# 任务 05：域化架构骨架（domains/ + registry）

## 背景

- 当前架构问题：`src/renderer/src/stores/appStore.js` 有 **1090 行**（虽已抽出 persistence/partsDomain/documentDomain/settingsDomain 四个文件，但仍是主状态中心）；`utils/knowledgeBase.js` 66KB 内容与检索逻辑混装；侧边栏菜单、路由、命令分散在 `App.vue`、`router/index.js` 各处。
- 升级目标（来自《升级规划》批次 0）：**域 = 数据表 + 页面 + 动作 + 命令 + 能力声明**，新功能（语音纪要域等）按域结构生长，旧功能渐进迁移。
- 本任务只搭**骨架 + 注册中心**，并**迁移一个最小的现有模块作为样板**（建议选 `stores/settingsDomain.js` 对应的"系统设置/演示参数"域，它是最小的自包含模块：meta 表读写 + 一个页面）。
- 安全网：288 条 self-check + 88 条 e2e；每步迁移一个域就跑 verify。

## 目标

1. 建立 `domains/` 目录规范与 `registry.js` 注册中心（菜单/路由/命令/能力声明的数据源）；
2. 侧边栏菜单改为由注册中心生成；
3. 迁移「系统设置」为第一个样板域（验证规范可行）；
4. 不破坏现有 15 个页面的任何功能。

## 改动清单

| 文件 | 动作 | 说明 |
|------|------|------|
| `src/renderer/src/domains/registry.js`（新增） | 注册中心 | 收集各域：`{ id, name, group, icon, route, component, commands, capabilities }`；提供 `getMenus()` / `getRoutes()` / `getCommands()` |
| `src/renderer/src/domains/settings/`（新增） | 样板域 | `domain.js`（设置状态/动作，从 settingsDomain.js 迁入）、`routes.js`、`commands.js`、`capabilities.js`、`views/Settings.vue`（引用迁移） |
| `src/renderer/src/App.vue` | 改侧边栏数据源 | 菜单从 `registry.getMenus()` 生成（保持现有视觉与分组不变） |
| `src/renderer/src/router/index.js` | 路由改注册生成 | `registry.getRoutes()` 拼到路由表（保留现有全部路由） |
| `src/renderer/src/stores/appStore.js` | 轻量化 | 设置相关状态/动作改为经域注入；避免删除行为，先解耦再清理 |
| `src/renderer/src/main.js` | 初始化注册中心 | 启动时 `registerDomains()` |

## 实现要点

- **域规范**（写入 `domains/README.md` 或 `domain-spec.md`）：
  ```
  domains/<name>/
    domain.js       状态、动作、持久化映射
    routes.js       页面路由注册
    commands.js     命令面板命令注册（本任务先定义接口，命令面板在任务 12 实现）
    capabilities.js 声明依赖的 AI 能力（narrate/diagnose/summarize/asr/ocr/parse）
    views/          本域页面
  ```
- **渐进原则**：只迁移 settings 一个域；其余 9 个现有域（设备/工单/备件/知识库/文档/日志/告警等）保持现状，后续任务逐个迁。
- **跨域联动**：现在 appStore 里"设置→health 参数覆盖（`configureHealth`）"这类联动，通过域暴露的接口调用，不直接改其他域内部状态。
- 侧边栏菜单**视觉必须与现在完全一致**（分组名、图标、顺序），只换数据来源，不换 UI。
- 自检脚本可加断言：注册中心返回的菜单/路由与现有配置一致（防迁移漏项）。

## 验收标准

1. `npm run verify` 全绿（lint / self-check 288+ / coverage / build / e2e 88 / e2e:nl / contrast）；
2. 侧边栏 5 分组 15 入口与升级前**逐项一致**；
3. 系统设置页功能完整（演示参数切换、告警处置、重置演示数据等）且写入 meta 表正常；
4. `registry.getMenus()` / `getRoutes()` 返回结构正确，settings 域的命令/能力声明存在；
5. appStore.js 行数下降（settings 相关代码迁出），且无遗留死代码（lint 无 unused）。

## 注意

- 这是架构任务，**宁可多花时间保证回归，不要追求一步到位**：只迁 settings，其余不动。
- 不引入新依赖；不改 UI 视觉；不动 health.js / nlCommand.js / llmClient.js / database.js。
- 如果迁移中发现 appStore 与 settingsDomain 耦合过深（函数声明提升、闭包注入），如实记录解耦步骤，不要用"复制一份状态"的偷懒方案（会出两套状态各说各话）。
