## 实现要点



* **档位定义**（Q4\_K\_M 量化，体积为估算，以实际文件为准）：



| 档位        | 模型                        | 体积      | 最低内存 | 能力                             |
| --------- | ------------------------- | ------- | ---- | ------------------------------ |
| light（默认） | Qwen2.5-0.5B-Instruct（现有） | 468MB   | 任意   | narrate（叙述润色）                  |
| standard  | Qwen2.5-1.7B / Qwen3-1.7B | \~1.1GB | 8GB  | narrate + diagnose + summarize |
| enhanced  | Qwen3-4B                  | \~2.5GB | 16GB | + 复杂推演                         |



* 模型文件可能不在本地（分发方案见任务 07）—— 注册表要区分「已安装 / 未安装」，未安装档位在 UI 显示 "待下载 / 待放入"。

- **自动选档**：主进程探测（`os.totalmem()`），8GB 以下选 light，8-16GB 选 standard，16GB 以上选 enhanced；结果可被手动切换覆盖并持久化（写 `userData` 下的配置文件或通过 IPC 告知渲染层存 meta）。

- **能力分级**：`capabilities` 数组声明；渲染层根据当前档位能力决定功能入口显隐（如 diagnose 相关入口只在 standard+ 显示）—— 本任务先定义能力模型，入口灰度的具体页面改造跟随对应功能任务。

- **释放语义**：`switchModel` 时先 `context?.release?.()` / 置空 model/context/completion，再加载新档；切换失败回退原档，状态机保持可观测。

- 数字不变量校验逻辑不动（在 llmClient.js），任何档位输出路径一致。

- 注意 node-llama-cpp 是 ESM-only，主进程必须用动态 `import()`（现状已如此，保持）。
