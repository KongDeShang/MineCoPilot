# 任务 08：统一文档解析（docService：PDF / Excel / Word）

## 背景

- 现状：PDF 解析在 `utils/pdfExtract.js`（pdfjs-dist 按需动态加载，供手册库 `stores/documentDomain.js` 用）；Excel 解析在 `utils/excelParser.js`（SheetJS，供 `components/ExcelImportPanel.vue` 用）；**没有 Word 解析**；两个解析入口各自为政、错误语义不统一。
- 目标：收敛为**一个 `docService`**——`parse(file) → { format, name, pages, text, tables[], images?, raw }`，任何域"丢进一个文件 → 拿到结构化文本"；Word 支持用 mammoth.js（纯 JS、零 .node、符合离线铁律）；解析结果**按文件哈希+大小缓存**，二次打开秒出（一并解决手册库首启抽文字层十几秒的问题）。
- 依赖：任务 05 域化规范（docService 作为能力服务，供各域声明 `capabilities: ['parse']`）。

## 目标

1. `utils/docService/`：统一接口 + 三格式适配器（pdf / excel / word / txt）+ 缓存层；
2. 现有调用方（Documents.vue 手册库、ExcelImportPanel）改走统一入口，行为不回归；
3. 结构化错误语义：`{ ok:false, error, reason: 'no_text_layer' | 'unsupported' | 'corrupt' | 'too_large' }`。

## 实现要点

- **缓存**：key = `sha256(file.slice(0, 64KB)) + size`（大文件只哈希头部够用，或全量哈希权衡）；存 IndexedDB（浏览器）/ `userData/doc-cache/`（Electron 经 IPC，可先只做 IndexedDB 统一方案，Electron 下 IndexedDB 也在 userData）；缓存记录 `{ format, pages, text, tables, extractedAt }`。
- **错误语义**：PDF 无文字层 → `reason:'no_text_layer'`（现有"扫描件仅查看"降级逻辑据此判断）；未知扩展名 → `unsupported`；解析异常 → `corrupt`；超限 → `too_large`。
- **统一文本产出**：Excel 多 Sheet 合并为 Markdown 风格表格文本（现有 excelParser 已有类似产出，保持格式稳定，别改坏自检断言）。
- **切片打通 RAG**（本任务可选做基础版）：`parse` 结果按页/章节切为 `{ docId, page, text }` 列表返回，供后续文档问答域使用；切片逻辑放 docService，不进页面。
- 自检脚本可加断言：三格式样例文件 parse 成功、错误语义正确（造小样例文件放 `scripts/fixtures/`）。

## 验收标准

1. `npm run verify` 全绿（Excel 导入路径、手册库路径的既有断言通过）；
2. 手工：拖入 PDF（含文字层）/ 扫描件 PDF / xlsx 多 Sheet / docx / 伪 .doc / 超限文件，各返回预期结果与错误语义；
3. 同一文件二次解析命中缓存（可打印/断言缓存命中）；
4. Word 解析正常（docx 中文不乱码）；
5. `npm run lint` 0 错。

## 注意

- 保持 Excel 多 Sheet 合并与字段对齐的**既有行为**（e2e/self-check 有断言），只换入口不换逻辑。
- 老 .doc 不支持要如实返回 unsupported + 界面提示转存，不要硬撑。
- 不动 health.js / nlCommand.js / llmClient.js / database.js。
