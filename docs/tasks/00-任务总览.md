> 用法：**每次只把一个任务文件（01~15）的内容发给执行 AI**，做完验收后再发下一个。
> 任务按依赖排序，编号即推荐执行顺序。每个任务自包含背景/改动/验收，无需阅读本文档以外的规划文档。

## 项目速览（所有任务共用背景）

- **项目**：矿山智工（`D:\徐工`）——全离线矿山工程机械运维 AI 工作台，参赛「中国创新创业大赛 AI+工程机械专业赛」。
- **技术栈**：Vue 3 + Element Plus + Pinia + Vue Router + ECharts（渲染层）；Electron（contextIsolation + sandbox + preload 白名单，主进程）；sql.js（本地 SQLite，Electron 落盘 `userData/*.db`，浏览器走 IndexedDB）；node-llama-cpp + Qwen2.5-0.5B（本地叙述模型）。
- **目录要点**：`src/main/`（Electron 主进程+LLM 引擎）、`src/preload/`（contextBridge 白名单）、`src/renderer/src/`（views 15 页 / components / stores（appStore 主状态）/ utils（health、nlCommand、knowledgeBase、database 等）/ styles（tokens.css））、`scripts/`（验收脚本）、`resources/models/`（本地模型，不随 git 分发）。
- **三条铁律（任何修改不得破坏）**：
  1. 运行期零联网、无任何云端 API key（`src/` 内无对外网络请求）；
  2. 数据不出本机（Electron 落 userData，浏览器走 IndexedDB）；
  3. 数字不变量校验：大模型生成文本中的数字必须 ⊆ 规则引擎结论的数字集合（`utils/llmClient.js` 的 `verifyNumbersSubset`），失败静默回退规则引擎原文。
- **验收命令**：`npm run verify` = lint + self-check + main-check + store-check + coverage + build + e2e + e2e:nl + contrast-audit（浅色 16 路由；另有 `npm run audit:contrast:dark` 跑深色 16 路由）。每个任务完成后至少跑相关部分，改动到业务逻辑必须跑全量 verify。**断言条数以脚本末行"合计 N 项"为准**，本文不写死数字。
- **不动清单**：`utils/health.js`（健康评分）、`utils/nlCommand.js`（口述解析核心）、`utils/llmClient.js`（数字不变量校验）、`utils/database.js`（数据库层）——只增不改。
- **已知状态**：以脚本实际输出为准（本文不写死断言条数）。2026-09-17 实跑：lint 0 错 0 警 / self-check 332 通过 / main-check 17 通过 / store-check 20 通过 / coverage 通过 / e2e 102 通过 / e2e:nl 28 通过 / 对比度（浅色 + 深色各 16 路由）全达标 / 运行时异常 0 / 生产构建成功（最大 chunk 为 vendor-echarts 614KB，无 700KB 告警）。npm audit 因镜像源不支持无法执行。**2026-09-25 实跑（完善计划第一批后）**：lint 0 错 0 警 / self-check 332 通过 / main-check 17 通过 / store-check 40 通过 / coverage 通过 / e2e 125 通过 / e2e:nl 31 通过 / 对比度（浅色 + 深色各 16 路由）全达标 / 运行时异常 0 / 生产构建成功。**2026-09-25 实跑（第二批 P2-1 / P2-2 后）**：lint 0 错 0 警 / self-check 332 通过 / main-check 17 通过 / store-check 80 通过 / coverage 通过 / e2e 125 通过 / e2e:nl 36 通过 / 对比度（浅色 + 深色各 16 路由）全达标 / 运行时异常 0 / 生产构建成功。

> **2026-09-17 修复轮（28 类缺陷，未新增功能）**
>
> 一次完整审计（5 路并行 + 逐条代码复核）后集中修复，重点在"已宣布完成但其实没生效"的功能与静默失败的数据路径：
>
> - **数据安全（最高优先级）**：落盘失败原来被当成"保存成功"（`db:write` 的 `{ok:false}` 被丢弃、`dirty` 照样清空、关窗时因 `dirty=false` 直接跳过重写）—— 现在失败即抛错、保持脏状态以便重试、界面显示"保存失败"；"台账为空"原来被当成"全新安装"（会播种 60 台演示设备并**整库覆盖**用户数据），现在由 `utils/seedGate.js` 按"一条数据都没有 **且** 没有 `seed_version`"判定；库损坏原来静默新建空库（随后被播种覆盖），现在抛 `db-corrupt` 并保持原文件不动；导入台账为空的备份原来被换成演示数据还提示"恢复成功"，现在如实拒绝/如实告知；手册读取失败原来静默导出不含手册的备份，现在中止导出并报错。另发现并修复：导入备份会**删掉**聊天记录（判 `Array.isArray` 而实际存的是对象）。
> - **功能断链**：`preload` 传裸字符串、主进程读 `payload.id` ⇒「切换到该档」100% 失败（本机从未生成过 `model-pref.json`）—— 已修，并改为"先校验目标档已装好、失败则把原档加载回来"，不再先释放旧会话；`addEquipment` 白名单漏了 `aliases` ⇒ 新建的设备永远没有别名（只对编辑过的设备生效）；`nlActions` 里第三个日志窗口 `slice(0,50)` ⇒ 任何口述写入都会**永久删除**第 51 条以前的历史，现统一为 `LOG_WINDOW`；看板「查看全部」指向不存在的 `/alerts`（无 catch-all，点了白屏）；体检报告打印在 Electron 下必然打不开（`window.open` 被自家 `setWindowOpenHandler` deny）；`setWindowOpenHandler` 无条件 `openExternal`（含空串）已按协议白名单收敛。
> - **两处"看着有其实没有"**：体检报告预览因为根节点带 `.print-doc`（那份 CSS 写了 `display:none`）在屏幕上**全白** —— 所有断言全绿，因为断言读 `textContent` 不看可见性；告警中心内联了第二套扫描规则，与看板各算各的，且漏掉规则引擎里的「高频故障/极高频故障/闲置设备」—— 现统一消费 `alertRules.toAlertRows()`。
> - **验证网（这才是根）**：新增 `scripts/main-check.mjs`（17 项，用 `Module._load` 桩掉 electron，直接调用主进程真正注册的 IPC handler —— 此前 `src/main/**` 与 `src/preload/**` 只有一条正则检查，这正是档位切换能失败到底还全绿的原因）；新增 `scripts/store-check.mjs`（建时 20 项，后来陆续加断言 —— 现在以脚本末行"合计 N 项"为准，把 `utils/`+`stores/` 镜像进**项目内**目录以解析裸导入 `vue`/`pinia`/`sql.js`，在 Node 里真正装配 pinia 跑 appStore/persistence —— 此前这两个文件（1700+ 行）**0 行真实执行**，"白名单漏字段"与"空台账被当首启"都因此长期存活）；self-check 增加 19 项故障注入断言（落盘失败、播种判据 6 种状态组合、库损坏、告警口径一致性）；三者都接进 `npm run verify`。**每条新断言都做过"能失败"验证**：把 `aliases` 从白名单删掉，store-check 立刻两红、退出码 1、诊断精确到字段名，而同缺陷在旧自检里对应的四条源码字符串断言当时全绿。
